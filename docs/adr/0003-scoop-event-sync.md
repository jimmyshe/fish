# 铲屎计数采用事件流上报，失败即丢弃

联网玩法中，客户端每次铲屎向服务器 POST 一个携带 UUID 幂等键的铲屎事件，服务器去重后累计铲屎计数；上报失败（断网、服务器不可用、被拒绝）直接丢弃，不做离线队列与补传；未登录时完全不产生计数。

## Considered Options

- **状态同步**（客户端维护总数、定期 PUT、服务器取 max）：多设备下总数互相覆盖，丢失时间维度，否决。
- **事件流 + 离线补传队列**：最终一致、不丢数，但补报事件的时间戳无法验证真伪，且队列引入本地持久化与合并 UI 的复杂度。对一个朋友间比铲屎数的游戏，丢数的代价低于这套机制的复杂度，否决。

## Consequences

- 周期榜（日/周）仍可由后端按事件时间戳推导，不受丢弃语义影响。
- 客户端不需要待同步队列，config 不新增相关字段。
- 限流 + 幂等去重是唯一的信任边界，不防蓄意作弊（小圈子内视为社会问题）。
