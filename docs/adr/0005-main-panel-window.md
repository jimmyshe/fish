# 主面板窗口：设置/排行榜合并为唯一 UI 窗口 + config-changed 单一同步缝隙

Status: accepted

此前设置与联网 UI 散落在三处：游乐场窗口内的草稿式设置弹窗（托盘「设置下班时间」经 open-settings 推送打开）、独立的联网窗口（排行榜 + 登录）、以及托盘/右键菜单里的一组勾选项（自启动、全局鼠标追踪、拉屎、置顶、显示/隐藏）。同一份配置有 setter 返回值、poop-enabled-changed 推送、菜单重建三条同步路径。我们将全部设置 + 登录 + 排行榜 UI 合并进一个新的独立 OS 窗口「主面板」：普通窗口（440×620、不置顶、不可缩放、单例、关闭即销毁），tab 导航分「⚙️ 设置」与「🏆 排行榜」两页，托盘菜单 deep-link 到对应 tab（窗口已开则聚焦并经 panel-switch-tab 推送切换）。游乐场窗口变为纯互动层（鱼、屎、气泡），不再含任何设置 UI 与右键菜单。配置同步收敛为一条缝隙：configStore.set 是唯一写点，set 即向所有窗口广播完整 Config（config-changed），renderer 一律「挂载先拉 getConfig、之后订阅 onConfigChanged」；设置项全部即时生效，无草稿/保存流。

## Considered Options

- **保留游乐场浮层设置弹窗**：命中检测要对面板做特例（面板开关时按光标位置补做命中检测），且透明全屏窗口里的弹窗没有原生窗口 chrome（拖动、关闭都要自己接线）；独立 OS 窗口把这些全部还给系统，放弃浮层方案。
- **保留托盘/右键菜单勾选项**：菜单勾选与面板并存 = 同一开关两个写入口，菜单需随配置重建；托盘只留入口后菜单变为纯静态三项，永远无需重建，放弃菜单勾选。
- **每个设置字段一条推送通道**（poop-enabled-changed 旧模式）：通道随字段数膨胀，且各窗口要分别订阅；单一 config-changed 广播完整 Config，消费方只挑自己关心的字段比对，通道数量与字段数解耦。

## Consequences

- 右键菜单整体删除（show-context-menu IPC、popupContextMenu、DesktopPet 右键处理），📌 置顶挪进主面板设置 tab（不持久化，默认开启，看门狗跳过逻辑不变）。
- 「👁 显示/隐藏」功能删除：游乐场窗口恒在，无隐藏入口。
- 托盘菜单固定三项：⚙️ 设置 / 🏆 排行榜 / ❌ 退出；不再展示下班时间、登录态、勾选项，auth 状态变更不再触发菜单重建。
- 联网窗口（network.html / NetworkPanel.vue）被主面板吸收：排行榜 tab 轮询语义不变（窗口存活且已登录 → 5 分钟轮询，窗口销毁即停）。
- 登录入口从托盘挪到排行榜 tab；登录失败改由 tab 内错误文案呈现，不再弹主进程错误对话框。
- 开机自启动的 setLoginItemSettings 调用从菜单模块挪到 set-auto-launch IPC 处理器（仅生产包生效）。
- 下班时间/下班提示/拉屎等单项 get 通道删除，renderer 统一走 getConfig + onConfigChanged；setter 通道保留但不再兼任同步（不返回完整 Config）。
- 设置从草稿式（取消/保存）改为即时生效，用户没有撤销入口，已接受（所有项都可随手改回）。
