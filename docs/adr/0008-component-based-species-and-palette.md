# 外观架构：物种与调色正交解耦及组件化模型自理表现

Status: accepted

在原 ADR 0006 中，「皮肤（Skin）」被宽泛定义为 18 色具名调色板（6 有效心情 × 身/尾/鳍）。随着后续引入更多全新造型（如不同鱼种或其他宠物生物），现有架构面临两大瓶颈：
1. **概念模糊**：原本单一的 `skin` 概念将“生物解剖形态（物种）”与“颜色（调色方案）”混为一谈。不同形态的生物可能没有鱼尾或鱼鳍，无法套用同一调色板；同时也有固定画风无需换色的物种。
2. **渲染与几何硬编码**：`DesktopPet.vue` 中内联了经典鱼的 SVG 标签，且 `usePetEngine.ts` 内部写死了眼球坐标跟随 `(84, 34)` 的几何尺寸，外层样式深度绑定了 `.fish-tail` 摆尾动画，导致添加新素材时无法自由发挥且极易破坏既有逻辑。

我们将宠物外观架构重构为**「物种（Species）与调色（Palette）正交解耦」**及**「组件化模型自理表现」**：

1. **领域实体正交化**：
   - **物种 (Species)**：宠物的生物/解剖形态与模型骨架（默认首发 `classic-fish` 经典小鱼），映射一个具体的 Vue 模型组件。
   - **调色方案 (Palette)**：特定物种支持的具名颜色方案（经典小鱼下含默认、金鲤、樱花、水墨、赛博）。
   - **联合身份**：外观由 `(speciesId, paletteId)` 联合确定，配置与 IPC 同步升级，对老版本 `skinId` 提供平滑自动迁移。
2. **组件化模型与单向 Props 契约**：
   - 提取首发模型为 `ClassicFishModel.vue`。
   - 定义标准的单向只读 `PetModelProps`（有效心情、鼠标位置、朝向、睡眠/受惊/排泄/彩虹标志、可选调色板）。模型组件纯声明式渲染，不向上触发业务事件。
3. **表现层职责严格划分（素材自理局部表现）**：
   - **全局外层机制**：对话气泡、飘浮粒子、屎实体与铲屎、连击徽章、窗口穿透与拖拽，统归外层宿主负责。
   - **素材内部自理**：眼球注视与眨眼计算、嘴型变换、泪水/汗水局部贴合、肢体游动动画（如摆尾/喷水）、专属彩蛋高亮（如皇冠/特效光圈），由模型组件内部全权私有自理。
4. **两层联动 UI**：
   - 主面板设置 Tab 中采用两层选择器：第一层药丸标签选「🐾 物种」，第二层根据所选物种动态展示其「🎨 调色」方案（固定原色物种展示专属标签，支持换色物种展示色块）。

## Considered Options

- **维持单一 Skin 字符串并在注册表隐式绑定组件**：继续沿用单一 `skinId` 虽然对配置改动最小，但会把物种选择与调色选择死板地拍平在一维列表里，随着新物种加入会导致设置面板色块按钮逻辑混乱，无法直观表达不同物种层级。
- **由外层壳统一计算眼睛与表情锚点**：在外层配置一个包含 `eyeOffset`、`mouthPath`、`sweatPos` 的庞大坐标元数据表。但这会导致外层引擎必须理解每种生物的解剖结构，对于非鱼类生物（如没有嘴巴、复眼、或者非矢量图形）会造成抽象泄漏和配置爆炸；让素材组件自理局部表现是内聚度最高的解法。
- **动态组件懒加载（defineAsyncComponent）**：在桌面端安装包环境下，静态模型体积仅数十 KB，动态引入不仅增加异步占位状态与打包分割复杂度，还会引发切皮肤时的白屏闪烁；采用强类型集中静态映射表最为稳健。

## Consequences

- 彻底消除了 `DesktopPet.vue` 和 `usePetEngine.ts` 对具体 SVG 路径与眼球几何 `(84, 34)` 的硬编码依赖。
- 未来新增任意新物种只需编写一个独立的 `.vue` 模型组件并在注册表添加一行定义，零侵入核心引擎。
- `GLOSSARY.md` 同步补充「物种」、「调色方案」、「模型组件」，修正「皮肤」词条。
- 主面板设置 Tab 进化为物种与调色的两层联动选择器。
